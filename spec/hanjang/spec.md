## 문제 — 모여도 바로 같이 할 게임이 없다

친구 4명이 한자리에 모여도 같이 켤 게임을 고르기 어렵다.
새 게임은 규칙을 설명하느라 시간이 든다.
다들 아는 원카드 규칙이면 설명이 필요 없다.
지금 레포에는 같은 와이파이로 붙는 술래잡기 시험판만 있다.

## 목표 — 같은 와이파이의 2~4명이 한장! 한 판을 끝까지 한다

방장이 방을 열고 친구들이 주소로 들어와 원카드 규칙으로 한 판을 끝까지 한다.
화면과 연출은 스토리보드 14장면을 따르고, 카드와 이름은 우리 것이다.
방장이 모든 판정을 하고, 각자는 자기 패만 본다.

## 비목표 — 기본 규칙 한 벌과 같은 와이파이까지만

- **하우스 룰**은 넣지 않는다. +2 쌓기 같은 선택 규칙은 다음 기능의 몫이다.
- 접속은 같은 와이파이 안까지다. 포트포워딩과 중계 서버는 인터넷 접속 기능의 몫이다.
- 사람만 한다. 빈자리를 채우는 봇은 봇 기능의 몫이다.
- 맥에서 돌리는 것까지다. 모바일 빌드는 하지 않는다.
- 이름과 로고에 UNO를 쓰지 않는다. 카드 그림도 우노 카드를 닮지 않게 그린다.

## 경계 조건 — 사람 수, 덱, 입력, 끊김을 아래처럼 처리한다

사람과 방

- 한 방에는 2명부터 4명까지 들어간다. 다섯째 사람은 "방이 꽉 찼어요"를 보고 참가 화면에 남는다.
- 판이 돌고 있는 방에는 들어갈 수 없다. "지금 게임 중이에요"를 보여 준다.
- 닉네임은 1자부터 8자까지다. 비어 있으면 다음 화면으로 넘어가지 않는다.
- 닉네임과 아바타가 남과 겹쳐도 막지 않는다. 자리 위치로 사람을 가린다.
- 자리는 들어온 순서대로 채운다. 첫 자리는 늘 방장이다.

덱과 카드

- 첫 카드는 숫자 카드가 나올 때까지 뒤집는다. 특수 카드는 다시 덱에 섞는다.
- 뽑을 덱이 비면 버린 더미의 맨 위 한 장만 남기고 나머지를 섞어 덱으로 만든다.
- 덱과 버린 더미가 둘 다 비면 뽑기 없이 차례만 넘어간다.
- 2명일 때 리버스는 스킵과 같다. 낸 사람이 한 번 더 한다.
- 와일드로 고른 색은 다음 사람이 맞출 색이 된다.

입력과 시간

- 차례가 아닌 사람의 요청은 방장이 무시한다. 패에 없는 카드와 낼 수 없는 카드 요청도 무시한다.
- 같은 사람이 같은 요청을 두 번 보내면 첫 번째만 받는다.
- 색 고르기 중에 시간이 다 되면 그 사람 패에 가장 많은 색을 고른다. 같으면 빨강부터 고른다.
- 바로 내기와 가지기 사이에서 시간이 다 되면 가진다.
- 잡았다! 를 여러 사람이 누르면 방장에게 먼저 닿은 요청 하나만 받는다.

끊김

- 판 중에 접속자가 나가면 그 사람 카드를 뽑을 덱에 넣고 섞는다. 남은 사람끼리 계속한다.
- 나간 사람의 차례였으면 다음 사람에게 바로 넘긴다.
- 남은 사람이 1명이 되면 판이 끝난다. 그 사람이 1등이고 나간 사람은 등수에서 빠진다.
- 대기실에서 나가면 자리만 빈다.
- 방장이 나가면 모든 접속자가 "방장이 나갔어요"를 보고 첫 화면으로 간다.

## 상태 모델 — 방은 다섯 단계, 차례는 네 단계를 돈다

방은 첫 화면, 대기실, 나눠 주기, 진행, 결과 순서로 움직인다.

| 지금 | 다음 | 언제 |
|---|---|---|
| 첫 화면 | 대기실 | 방을 만들거나 참가에 성공했을 때 |
| 대기실 | 나눠 주기 | 2명 이상에서 방장이 시작을 눌렀을 때 |
| 나눠 주기 | 진행 | 7장씩 다 나눠 주고 첫 카드를 뒤집었을 때 |
| 진행 | 결과 | 누가 패를 다 털었거나 남은 사람이 1명일 때 |
| 결과 | 나눠 주기 | 다시 하기를 골랐을 때 |
| 결과 | 대기실 | 대기실로를 골랐을 때 |
| 어느 단계든 | 첫 화면 | 방장이 나갔을 때 |

차례는 고르는 중, 색 고르는 중, 뽑은 카드 고르는 중, 한장! 판정 중을 돈다.
고르는 중에 와일드를 내면 색 고르는 중이 된다.
고르는 중에 뽑은 카드가 낼 수 있는 카드면 뽑은 카드 고르는 중이 된다.
2장에서 1장을 내면 한장! 판정 중이 된다.
나머지는 바로 다음 사람의 고르는 중으로 넘어간다.

있을 수 없는 조합

- 진행 중인데 패가 0장인 사람이 있다.
- 나간 사람에게 차례가 있다.
- 접속자 화면이 남의 패 카드 값을 갖고 있다.
- 색 고르는 중인데 버린 더미 맨 위가 와일드가 아니다.
- 접속자 화면의 시작 버튼이 눌린다.
- 대기실에 5명이 있다.

## 기술 결정 — 방장이 모든 판정을 하고 각자에게 자기 패만 보낸다

**방장 판정** — 덱, 모든 패, 차례, 시간은 방장만 가진다. 술래잡기 시험판도 방장이 판정했고, 속임수를 막으려면 이 방식이 필요하다.

**숨긴 정보** — 모두에게 같이 보내는 것은 더미 맨 위 카드, 정해진 색, 사람마다 남은 장수, 차례뿐이다. 패 카드 값은 그 사람에게만 따로 보낸다.

**규칙과 화면 분리** — 규칙 판정은 화면 없이 도는 코드로 둔다. 그래야 헤드리스로 규칙만 시험할 수 있다.

**자동 시험** — 방장과 접속자 셋을 헤드리스로 띄우고 로그로 판정한다. 시험판에서 이미 쓴 방법이다.

**한장! 판정 순서** — 여러 사람이 동시에 누르면 방장에게 먼저 닿은 요청이 이긴다. 같은 와이파이에서는 이 순서가 사람이 누른 순서와 거의 같다.

## DAG — 규칙과 룩을 먼저 두고, 화면 줄기와 네트워크 줄기를 나란히 돌린다

```
n1-rules ──┬─────────────────────► n4-session ──┐
           │                          ▲          │
n2-look ───┼──► n3-lobby ─────────────┘          ├──► n7-wire ──► n8-verify
     │     │                                     │
     │     └──► n5-table ──► n6-fx ──────────────┘
     └────────► n5-table
```

| 웨이브 | 노드 | 비고 |
|---|---|---|
| 1 | n1-rules, n2-look | n2는 막는 결정 D4 답을 기다린다 |
| 2 | n3-lobby, n5-table | 둘 다 n2 뒤. n5는 n1도 필요 |
| 3 | n4-session, n6-fx | 네트워크 줄기와 화면 줄기 |
| 4 | n7-wire | 두 줄기를 합친다 |
| 5 | n8-verify | 4인 실제 창과 스토리보드 대조 |

가장 긴 줄은 5개 노드다. 전체 8개 노드보다 짧다.

연결 사유

- n3 ← n2: 첫 화면과 대기실이 n2의 테마, 폰트, 아바타 부품을 쓴다.
- n4 ← n1: 세션이 n1의 규칙 엔진과 `snapshot_for` 형태를 쓴다.
- n4 ← n3: 세션이 n3의 자리 목록과 시작 신호를 쓴다.
- n5 ← n1: 판 화면이 n1의 판 상태 형태로 그려지고, 로컬 드라이버가 n1 엔진을 돌린다.
- n5 ← n2: 판 화면이 n2의 카드 그리기 부품과 테마를 쓴다.
- n6 ← n5: 연출이 n5 판 화면의 자리, 더미, 패 노드 위에 붙는다.
- n7 ← n4: 판 화면을 n4 세션의 판 상태와 요청 RPC에 묶는다.
- n7 ← n6: 연출까지 붙은 판 화면을 묶는다. n6 전에 묶으면 n6이 같은 파일을 다시 연다.
- n8 ← n7: 4인 실제 창은 모든 화면이 묶인 뒤에만 돈다.
