## 문제

- 로컬 판 화면과 방장 세션은 아직 따로 돈다.
- 판이 끝나거나 누가 나가도 게임이 멈추면 안 된다.

## 목표

실제 방에서 장면 01부터 14까지 이어진다. 판 화면은 세션이 보낸 판 상태로 그려지고, 결과와 끊김이 처리된다.

## 작업

1. `game/screens/table_net.gd`: n4 세션이 보낸 판 상태를 `apply_snapshot`으로, `action_requested`를 세션 요청 RPC로 잇는다.
2. `game/main.gd` 화면 전환에 판 화면과 결과 화면을 더한다.
3. 장면 13 결과: 등수, 남은 장수, 다시 하기·대기실로. D9 추천대로 방장이 고르고 접속자에게는 방장을 기다려요.
4. 장면 14 끊김: 나간 사람 회색, 연결 끊김 말풍선, 카드가 더미로 돌아가는 연출, 위쪽 알림.

## 구현 메모

- 관련 결정: D9 → 방장이 다시 하기·대기실로를 고른다 (2026-10-15 사용자 답).
- 웨이브 4 리뷰 넘김 (wave-20261015-1647.md), 메인이 정함:
  - 판 화면이 손을 정렬하면 카드는 손 인덱스 대신 카드 id로 보낸다. 정렬하지 않으면 인덱스 그대로 둔다.
  - 방장이 요청을 거절하면 그 접속자 판 화면의 입력 잠금을 푼다(n4가 보내는 거절 알림을 table.gd에 연결).
  - 시험용 봇·cheat·MYHAND 출력은 명령줄 인자가 있을 때만 켜지는지 확인만 한다. 따로 떼어 내지 않는다.
  - 요청 속도 제한은 넣지 않는다. 같은 와이파이 친구끼리라 비목표 범위다.
- 웨이브 6 리뷰 넘김 (wave-20261015-1716.md), 메인이 정함:
  - 판 화면을 세션에 묶을 때 `start_deal`(장면 04)과 `show_event`(한장!·잡았다!·+2·스킵·리버스 연출)를 세션이 보내는 사건에 연결한다.
  - 차례 시간은 나눠 주기 연출이 끝난 뒤부터 잰다. 방장 세션은 `fx_timing.gd`의 나눠 주기 길이만큼 기다린 뒤 첫 차례 시간을 시작한다.
  - 한장! 3초 창은 네트워크로 늦게 닿는 입력을 위해 방장 쪽에 0.3초 여유를 둔다. 창이 닫힌 뒤 닿은 요청은 무시하고 그 접속자의 버튼을 내린다.
- 느림 고침 (2026-10-15, 메인): 사용자가 두 창 실행이 느리다고 했다. 기본 Forward+(Metal)+수직 동기화에서는 8초 동안 FPS 보고가 0번이었고, Compatibility 렌더러에서는 125fps로 안정적이었다. 2D 픽셀 게임이라 `project.godot` 렌더러를 gl_compatibility로 바꿨다. 헤드리스 시험 8종(규칙·룩·판·연출·세션 경계·대기실·4인 판·연결) 모두 종료 코드 0.

- 만든 것: `table_net.gd/.tscn`(판 화면↔Session), `result.gd/.tscn`(장면 13), `main.gd`(판·결과 전환), `room.gd`(`replay()`, `back_to_lobby()`가 접속자에게도 대기실을 띄움, `lobby_returned`), `session.gd`(`event` 신호, 나눠 주기 동안 시간 정지, 한장! 0.3초 여유), `table_fx.gd`(`disconnect_fx`, 장면 14), `table.gd`(`unlock()`), `fx_timing.gd`(`deal_total`).
- 브리프 넘김 반영: 카드는 손 인덱스 대신 id로 받아 인덱스로 바꿔 보낸다(손 정렬은 없음). 거절 알림이 오면 입력 잠금을 풀고, 거절된 한장!·잡았다!면 버튼을 내린다. 차례 시간은 `FxTiming.deal_total`만큼 뒤부터 잰다(그동안 요청은 "나눠 주는 중이에요"로 거절하고, 끝나면 상태를 한 번 더 보낸다). 한장! 창은 방장 쪽만 3.3초(화면 표시는 3초).
- 시험용 봇·cheat·MYHAND: 봇(`--autoplay`)과 cheat(`--cheat`)는 명령줄 인자가 있을 때만 켜진다. MYHAND 출력은 인자와 무관하게 항상 stdout에 찍힌다(자기 패만). 떼어 내지 않고 확인만 했다.
- 시험: `game/tests/test_wire.sh`(헤드리스 프로세스 2~3개로 다시 하기·대기실로·판 중 나감) 통과, 기존 `test_net_game.sh`·`test_lobby.sh`·`test_rules/session_edge/table/fx` 통과. 시험 인자 `--result-pick=replay|lobby`(방장이 결과 1초 뒤 고름), `--keep-open`(자동 플레이 후 종료 안 함)을 더했다.
- 갭(실경로): 한 판 진행은 `--autoplay` 봇이 `Session.request`로 보냈다. 카드 클릭→table_net→세션 경로, 결과 화면 버튼 클릭, 실제 창 두 개(`두창으로_테스트.command`)는 돌리지 않았다. 완료 기준 2~4번째 항목을 체크하지 않은 이유다. 장면 13·14 캡처는 로컬 드라이버와 가짜 세션 값으로 만든 것이다.
- 가정: 결과 화면은 `ended` 2.2초 뒤에 뜬다(마지막 카드 연출을 보이려는 값). 다시 하기에서 나간 자리는 비우고 남은 사람이 2명 미만이면 대기실로 보낸다. 대기실로에서도 나간 자리는 비운다.

## 확인할 것

실제 창 두 개로 한 판을 끝까지 돌려 본다. 헤드리스 봇으로는 돌았지만 손으로 누르는 경로와 화면은 사람이 본다.

- [ ] `두창으로_테스트.command`로 한 판을 끝내면 결과 화면(장면 13)에 등수와 남은 장수가 뜨는가 (evidence/n7/13-result-host)
- [ ] 방장에게는 [다시 하기]·[대기실로], 접속자에게는 "방장을 기다려요"만 보이는가
- [ ] 다시 하기를 누르면 같은 둘이 나눠 주기부터 다시 시작하는가
- [ ] 결과에서 대기실로를 누르면 자리가 그대로인 대기실이 뜨는가
- [ ] 판 중에 접속자 창을 닫으면 그 아바타가 회색이 되고 말풍선·위쪽 알림·카드 날기가 보이며 남은 사람끼리 이어지는가 (evidence/n7/14-disconnect)
- [ ] 나눠 주기 길이만큼 첫 차례 시간이 늦게 시작되는 게 어색하지 않은가
