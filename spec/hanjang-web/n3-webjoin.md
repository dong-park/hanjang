## 문제

- 새 전송 위에서 브라우저 참가가 아직 안 돈다.
- 접속 실패와 화면 꺼짐을 처리해야 한다.

## 목표

휴대폰이 맥 앱 방에 들어가 한 판을 끝낸다

## 작업

1. 웹 빌드가 D7 답대로 방장 주소를 정해 참가한다.
2. 꽉 참, 게임 중, 방 없음 문구를 앱과 같이 보인다.
3. 화면 꺼짐·탭 전환을 나간 사람으로 처리한다.
4. 맥 + 실제 휴대폰으로 한 판을 돈다.

## 구현 메모

- (메인 추가, 웨이브 1 /review가 넘긴 것) 판 중 휴대폰 화면 잠금·앱 전환으로 웹소켓이 끊기면 같은 판에 다시 못 들어온다(room.gd _hello가 PLAYING이면 거절). 이 노드에서 같은 닉네임 재접속으로 자리를 되찾는 경로를 넣는다(최소: 끊긴 자리 유지 + 같은 닉네임 _hello 허용). 대기실 주소는 IP.get_local_addresses() 첫 사설 주소라 Docker/VPN이 있으면 틀릴 수 있으니 D7 자동 채움과 같이 점검한다. 사용자 지시로 자동화 진행 중이라 결정 행 없이 추천대로 넣는다.
- 주소 자동 채움: 웹이면 JavaScriptBridge로 window.location.hostname을 가져와 join 화면에 채운다(Room.page_host). 포트는 7777 고정.
- 재접속: 판 중 끊긴 자리(gone)를 같은 닉네임이 되찾는다(room.gd _hello → _rejoined, session.gd _on_peer_rejoined, rules.gd rejoin). 돌아온 사람은 패를 처음 장수만큼 새로 받는다(끊길 때 패는 더미로 돌아갔다). 판이 끝났으면 못 돌아온다. test_rejoin.sh로 확인.
- 대기실 주소: 192.168. → 10. → 172. 순, Docker 172.17.은 맨 뒤.
- 화면 꺼짐·탭 전환: 브라우저가 소켓을 닫으면 기존 peer_disconnected 경로로 나간 사람 처리된다. 별도 JS 훅은 넣지 않았다(미확인: 실제 iOS 잠금 때 소켓이 얼마 뒤 끊기는지).
- 미확인: 실제 휴대폰으로 한 판. 같은 닉네임이 아직 안 끊긴(gone 아님) 자리는 되찾지 못한다.

## 확인할 것

맥에서 앱으로 방을 열고, 휴대폰 브라우저로 같은 주소의 웹 페이지를 연 다음 닉네임만 치고 참가해 한 판을 끝까지 해 보세요. 중간에 휴대폰 화면을 껐다 켜서 같은 닉네임으로 다시 들어오는 것도 봐 주세요. 에뮬레이션 캡처는 evidence/n3에 있습니다.

- [ ] 주소를 치지 않아도 참가 화면에 방장 주소가 채워져 있다
- [ ] 맥 대기실에 휴대폰 자리가 생기고 한 판이 끝까지 돈다
- [ ] 화면을 껐다 켜면 같은 닉네임으로 자리를 되찾는다
