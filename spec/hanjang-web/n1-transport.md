## 문제

- ENet은 브라우저에서 못 연다.
- 앱도 같은 전송을 써야 같은 방에 들어간다.

## 목표

앱이 D1 답의 전송으로 방을 열고 참가한다

## 작업

1. D1, D2 답을 읽는다. 답이 없으면 추천대로 가고 구현 메모에 적는다.
2. `game/net/room.gd`의 방 열기·참가를 새 전송으로 바꾼다. 방 주소와 포트 규칙을 정한다.
3. 기존 헤드리스 시험과 두창·네창 시험을 새 전송으로 돌린다.
4. `main.gd`, `session.gd`는 다른 웨이브가 커밋한 뒤에만 열고, 필요한 최소만 고친다.

## 완료 기준

- [ ] 맥 창 2개에서 한 판이 끝난다
- [x] 4인 헤드리스 시험이 통과한다
- [x] 새 전송에서 맥 앱 서버가 열리는지 확인했다 (확인 안 된 것 해소)
- [x] 앱 시험이 그대로 통과한다 (헤드리스 시험 종료 코드 0)
- [x] 내 파일만 경로로 지정해 add한다

## 구현 메모
- D1=A(웹소켓), D2=A(휴대폰은 참가만) 답이 시트에 있어 그대로 따랐다.
- `game/net/room.gd`만 바꿨다. `WebSocketMultiplayerPeer`로 `create_server(port)`, `create_client("ws://주소:포트")`. 포트 7777 그대로.
- 방 주소 규칙: `ws_url()` — "192.168.0.5"는 기본 포트, "192.168.0.5:7778"은 그 포트, "ws://" 접두는 있어도 없어도 된다. 헤드리스 시험의 `--join=127.0.0.1 --port=N` 그대로 돈다.
- 웹소켓 서버에는 최대 접속 수 인자가 없어 다섯째·여섯째도 접속은 받고 자리에서 거절한다(전과 같은 문구). 시험으로 확인.
- 맥 4.7.2에서 웹소켓 서버가 열리는 것은 헤드리스 시험(대기실·세션·판 화면)으로 확인했다. 맥 창 2개 실화면 시험(두창으로_테스트.command)은 이 환경에서 돌리지 않았다 — 사람 확인.
- `main.gd`, `session.gd`는 열지 않았다.
- 접속 상한: 처음엔 없앴다가 웨이브 /review 지적(같은 와이파이에서 연결 남발)으로 `_on_peer_connected`에서 ENet 때와 같은 MAX_PLAYERS+3을 넘으면 끊게 되돌렸다. 다섯째의 "방이 꽉 찼어요"는 그대로(test_lobby 통과).

## 확인할 것

전송을 웹소켓으로 바꾼 뒤 헤드리스 시험(대기실·세션·판 화면·단위)은 모두 통과했습니다. 맥 창 2개로 실제 화면에서 한 판을 끝내는 시험은 돌리지 않았으니, `두창으로_테스트.command`를 열어 아래를 봐 주세요.

- [ ] 맥 창 2개에서 방을 열고 참가해 한 판이 끝까지 간다
- [ ] 결과 화면까지 끊김이나 오류 문구가 없다
