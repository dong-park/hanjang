## 문제 — 앱을 깐 맥 사람만 한장!을 할 수 있다

맥 앱은 완성됐다. 휴대폰을 가진 친구는 앱을 깔 수 없어 같이 못 한다.
지금 네트워크는 브라우저가 못 쓰는 UDP다.

## 목표 — 휴대폰 브라우저가 맥 앱 방에 들어가 같이 한 판을 끝낸다

친구는 주소를 열어 닉네임만 넣고 참가한다.
맥 앱과 휴대폰이 한 방에서 섞여 4명이 한 판을 끝낸다.
규칙, 연출, 숨긴 정보는 맥 앱과 같다.

## 비목표 — 참가까지다. 방 열기와 바깥 접속은 다음 기능이다

- 휴대폰이 방장이 되는 기능은 D2 답이 바뀔 때의 다음 기능이다.
- 인터넷 접속과 중계 서버는 `hanjang`의 비목표를 따른다.
- 규칙 변경과 새 연출은 하지 않는다.
- 앱스토어 배포와 홈 화면 앱 설치는 하지 않는다.
- 안드로이드 기기 시험은 이번에 하지 않는다. 브라우저 호환은 아래 확인 안 된 것으로 둔다.

## 성공 기준 — 행 파일이 곧 성공 기준이다

행 파일이 곧 성공 기준이다.

## 경계 조건 — 이 기능이 새로 만드는 경계

- 방이 꽉 찬 경우, 게임 중인 경우, 방장이 없는 경우의 문구는 앱과 같다.
- 휴대폰 화면이 꺼지면 접속이 끊긴다. 나간 사람과 같이 처리한다.
- 맥 앱과 휴대폰이 같은 방에 섞여도 판정은 방장 맥 하나가 한다.
- 맥이 꺼지면 모든 휴대폰은 "방장이 나갔어요"를 보고 첫 화면으로 간다.
- 같은 와이파이 밖에서는 페이지가 열리지 않아도 된다.

## 기술 결정 — 전송 하나를 앱과 웹이 같이 쓴다

방장이 모든 판정을 하는 구조는 그대로 둔다.
전송만 D1 답으로 바꾸고 앱도 같은 전송을 쓴다. 앱이 ENet을 두면 같은 방에 섞일 수 없기 때문이다.
화면 크기와 입력은 웹 쪽만 다르다. 앱 동작은 바뀌지 않아야 하고 T11이 그것을 잰다.

## 확인 안 된 것 — 조사를 하지 않아 모두 미확인이다

- 웹소켓 서버가 이 Godot 4.7.2의 맥 앱에서 열리는지.
- 웹 내보내기 템플릿이 4.7.2용으로 구할 수 있는지, 그리고 gl_compatibility 렌더러로 iOS Safari에서 도는지.
- 스레드 없는 내보내기가 4.7.2에서 가능한지.
- 화면 키보드가 Godot 입력칸에서 iOS Safari에 뜨는지.
- 휴대폰 가로 화면에서 카드 크기가 손가락으로 누를 만한지.
- 안드로이드 Chrome에서 되는지.

## DAG — 전송과 웹 내보내기를 나란히 돌리고, 그 위에 참가와 터치를 얹는다

| 웨이브 | 노드 | 비고 |
|---|---|---|
| 1 | n1-transport, n2-webexport | 서로 파일이 겹치지 않는다 |
| 2 | n3-webjoin, n4-touch | 둘 다 n1·n2 뒤. n4는 n2만 필요 |
| 3 | n5-verify | 실제 휴대폰 |

```
n1-transport ──┬──► n3-webjoin ──┐
               │                 ├──► n5-verify
n2-webexport ──┼──► n4-touch ────┘
```

연결 사유

- n3 ← n1: 웹 참가가 새 전송 위에서만 된다.
- n3 ← n2: 휴대폰이 열 웹 빌드가 있어야 한다.
- n4 ← n2: 터치와 화면 방향은 웹 빌드를 실제 폰에서 열어야 시험할 수 있다.
- n5 ← n3, n4: 모든 것이 합쳐진 뒤에만 4인 혼합이 돈다.
