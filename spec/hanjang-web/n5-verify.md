## 문제

- 맥과 휴대폰 섞인 4인 판을 아직 해 본 적이 없다.

## 목표

맥 2 + 휴대폰 2로 한 판을 끝내고 다시 한 판 한다

2. 실제로 본 것만 적는다.
3. 코드는 고치지 않는다.

## 구현 메모
- (메인 추가, 웨이브 2 /review가 넘긴 것) n5에서 재볼 것: iOS가 FIN 없이 끊을 때 방장이 끊김을 늦게 알아 재접속이 "게임 중"으로 거절되는지(미확인), 재접속 뒤 0.3초 타이머 전송 경합, test_wire 판 중 나감 경우 간헐 실패(3회 중 1회). 정책으로 남긴 것(고치지 않음, 최종 보고에 적는다): 재접속이 닉네임만 봐서 같은 와이파이 누구든 자리를 가져갈 수 있음(방 비밀값/토큰 결정 필요), 재접속 시 패를 장수만 보존하고 새로 뽑음. 사람 실기 확인(웨이브 1~2 미확인 항목)은 자동화 지시로 미뤄졌으니 n5 확인 대기에 모아 둔다.
- (n5 자동화 결과, 코드는 고치지 않음. 근거는 evidence/n5/, 도구는 tools/n5_*.) 맥 1=방장(네이티브 Godot), 맥 2=네이티브 Godot 접속자, 폰 2=Playwright WebKit iPhone 13 가로 웹 빌드(웹은 --autoplay 인자로 자동 플레이). 모두 같은 PC 루프백이고 실제 와이파이·실기가 아니다.
- 한 판 + 다시 하기(full-headless, 4명): 4자리 모두 채움, 한 판 끝, 방장이 다시 하기, 두 번째 판도 끝(RESULT 2회, REPLAY seats=4). 접속자 LEAK 0건, 폰 콘솔 error 0건. 창 모드(full-windowed)에서 맥 2는 실제 창 캡처로 한 판 끝까지 돌았다(맥 창 캡처는 한 판 뒤 앱이 닫혀 다시 하기는 헤드리스 쪽에서만 봄).
- (a) 끊김을 방장이 아는 시간. 폰 탭을 강제로 닫으면(브라우저가 FIN을 보냄) PEER_LEFT_IN_GAME까지 0.2초 안, 곧바로 같은 닉네임 재접속 성공(drop-fin). FIN 없는 끊김(중계가 그 연결의 바이트만 버리고 소켓을 열어 둠, drop-nofin)은 240초를 기다려도 방장이 끊김을 모르고, 약 8초 간격 재접속 31번이 전부 "지금 게임 중이에요"로 거절됐다(캡처 있음). 그동안 판은 자리 시간 초과 자동 처리로 계속 갔다. 즉 iOS 잠금 같은 FIN 없는 끊김에서는 소켓이 정리될 때까지 같은 닉네임으로도 못 돌아온다(웹소켓 서버에 ping·유휴 끊기 설정이 안 보임, 확정은 실기 필요). 고칠 길(범위 밖, 정하지 않음): 방장 쪽 주기 ping/타임아웃, 또는 같은 닉네임이 새 연결로 오면 옛 연결을 끊고 자리를 넘기는 정책(아래 토큰 결정과 함께).
- (b) 재접속 뒤 0.3초 타이머 전송: 재접속 시험 로그 11개에서 접속자 쪽 순서는 매번 REJOINED_OK → GAME_STARTED → SCREEN table_net → 첫 MYHAND였고 REJOIN_DESYNC·LEAK 0건. 0.3초 사이 방장이 자동으로 낸 턴(AUTO_DRAW)이 있어도 같은 순서였다. 경합 이상은 관찰하지 못했다(실제 와이파이 지연에서는 미확인).
- (c) test_wire: 6회 연속 통과(회당 382초). 전 웨이브의 3회 중 1회 실패는 재현되지 않았다. 다만 test_rejoin이 11회 중 6회 실패했다(통과 5). 실패는 모두 호스트 --quit-after=60 안에 판이 안 끝나 RESULT가 없는 경우이고, 로그상 재접속 자체는 성공했고 판도 계속 진행 중이었다(DESYNC·LEAK 없음). 판 길이가 달라 생기는 시험 길이 문제로 보이며 코드 결함 증거는 못 찾았다. 시험 코드는 고치지 않았다.
- 소음: 거절 때마다 Godot가 ERROR: Condition "!peers_map.has(p_peer_id)" 를 찍는다(room.gd _hello의 disconnect_peer가 이미 닫힌 연결에 호출됨). 동작에는 영향이 없다.
- 정책으로 남긴 두 건(고치지 않음): ①재접속이 닉네임만 봐서 같은 와이파이의 누구든 끊긴 자리를 가져갈 수 있다(방 비밀값/토큰 결정 필요) ②재접속하면 패를 나갈 때 장수만 보존하고 새로 뽑는다.
- 미확인(실기 필요): iOS Safari 실기 한 판, 실제 FIN 없는 끊김(iOS 잠금·와이파이 이탈)에서 소켓이 정리되는 시간, 화면 키보드·한글 IME·주소창, 실제 손가락 제스처, 웨이브 1~2 확인 대기 항목 전부, 실제 와이파이에서의 맥+폰 동시 한 판.
- 재현: python3 tools/n5_lock.py python3 tools/n5_scenarios.py full-headless|full-windowed|drop-fin|drop-nofin (웹 빌드 필요: tools/export_web.sh). 헤드리스 잠금은 /tmp/hanjang-headless.lock.

## 확인할 것

자동화로 맥 2(네이티브 Godot)와 폰 2(WebKit 아이폰 가로 에뮬레이션)를 한 방에 모아 한 판과 다시 하기를 돌렸고, 탭 강제 닫기와 FIN 없는 끊김도 재현했습니다. 실제 맥 1대와 실제 아이폰 2대가 같은 와이파이에서 한 판을 하고, 중간에 아이폰 하나의 화면을 잠갔다 켜서 아래를 봐 주세요. 아이폰이 잠겨도 방장이 한동안 끊김을 모르고 재접속이 거절될 수 있습니다.

- [ ] 맥 + 아이폰 2대가 한 방에서 한 판을 끝까지 하고, 다시 하기로 한 판 더 한다
- [ ] 아이폰 화면을 잠갔다 켜면 같은 닉네임으로 자리를 되찾는다. 안 되면 몇 초 뒤에 되는지 적는다
- [ ] 아이폰에서 닉네임 키보드·한글 입력이 가려지지 않고 카드 두 번 눌러 내기가 된다
- [ ] 같은 와이파이 다른 사람이 끊긴 닉네임으로 자리를 가져가는 것을 허용할지 정한다(방 비밀값 결정)
